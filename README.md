# Factorio (Android, native ARM64)

Форк Winlator, оставленный только ради запуска **нативного ARM64-билда Factorio** на Android
(glibc rootfs + Turnip/Zink/Vortek, мост геймпадов Selkies input interposer).
Wine, Box64, DXVK, VKD3D, WineD3D, Win-компоненты, ярлыки, MIDI и файловый менеджер вырезаны.

*Fork of Winlator reduced to run the native ARM64 build of Factorio. Wine/Box64/DXVK/VKD3D/etc. are removed.*

## Интерфейс
* Один встроенный контейнер (создаётся автоматически при первом запуске), списка контейнеров нет.
* Единые **Настройки** (контейнер: размер экрана, драйверы, звук, переменные среды + мышь, геймпады, язык/тема, логи):
  пункт в самом низу боковой шторки в игре и в главном меню приложения, а также долгое нажатие на значок приложения.
* После сохранения из игры предлагается перезапуск, чтобы настройки применились.

## Сборка
Открыть `app/` в Android Studio (AGP 7.2.2, NDK 24.0.8215888, ABI arm64-v8a). Игру положить в
`Download/factorio` (Linux arm64 билд) — при первом запуске она копируется в rootfs.

## Имя пакета больше не зашито
Любое имя пакета работает **без пересборки rootfs и драйверов**:

* в архивах (`rootfs.tzst`, `graphics_driver/*.tzst`, установочных компонентов) вместо
  `/data/data/<пакет>/files/rootfs` лежит маркер `/data/data/@@@@@@@@@@@@@@@@@@@@@@@@@` (ровно 36 байт);
* при распаковке (`core/PackagePath.java`, вызывается из `TarCompressorUtils`) маркер заменяется на
  `/data/data/<пакет>/r///…` (добивается `/` до 36 байт — повторные слэши в путях безвредны);
  `<dataDir>/r` — симлинк на настоящий `files/rootfs`, его создаёт `App.onCreate`;
* нативный код берёт имя пакета из `/proc/self/cmdline` (`getAppCacheDir()` в `winlator.h`);
* Java-пакет классов остаётся `com.factorio` (JNI-имена не меняются), меняется только пакет приложения:
  `applicationId` в `app/app/build.gradle` или `package` в манифесте (MT Manager / apktool).

**Ограничение:** имя пакета — не длиннее **23 символов** (запас в 36-байтовом слоте). Например
`com.antutu.ABenchMark` (21) подходит. Если длиннее — приложение покажет сообщение и закроется.

Старые пути `/data/data/com.winlator/files/rootfs` и `/data/data/com.factorio/files/rootfs` в архивах
тоже распознаются, так что компоненты из апстрима Winlator устанавливаются корректно.

## Пересборка нативных частей гостя
Исходники `android_alsa/`, `.github/workflows/*` уже используют маркер как префикс —
собранные библиотеки можно класть в архивы как есть. Маркер должен остаться ровно 36 байт.

### r34: встроенный OpenGL

Freedreno KGSL Mesa r7 встроен в APK. На Adreno OpenGL выбран по умолчанию для новых настроек. В разделе графического драйвера доступны OpenGL и Zink; изменение применяется при следующем запуске игры. `NATIVE_MESA_SRC` больше не перекрывает выбор и не требуется. Прежние настройки с этой переменной однократно переводятся на OpenGL. Игровые файлы по-прежнему нужны отдельно. Системные драйверы не изменяются.

Сборка assembleDebug и локальная проверка распаковки, повторного запуска и восстановления неполной установки прошли. Переключение OpenGL → Zink → OpenGL на телефоне для r34 пока не проверено. Настройки частот GPU не изменялись.

### r34-clean: первый запуск

OpenGL лежит в APK как `graphics_driver/opengl-kgsl-r7.tzst` (распаковывается через общий `TarCompressorUtils`).
При первом запуске, пока копируются файлы игры, внизу экрана предлагается выбрать разрешение: 720p, 1080p или нативное.
Ширина считается по реальному соотношению сторон экрана (например 1600x720 для 20:9), значение сохраняется
в контейнере и в любой момент меняется в настройках («Разрешение экрана» / «Пользовательский»).

### r34-clean: драйверы

Выбор Vulkan-драйвера упрощён: остался только Turnip (Vortek, «Авто» и драйверы Mali/bionic удалены).
Встроенные версии Turnip: 26.2.0 (по умолчанию), 26.2.4 и 26.3.0-beta. Свою сборку можно поставить из файла `.tzst`
иконкой установки в окне «Turnip Конфигурация» (тип драйвера определяется по содержимому архива).
Старые контейнеры с Vortek автоматически переходят на Turnip.

### r34-clean: сжатие текстур при копировании игры

После выбора разрешения на первом запуске предлагается сжатие текстур: «Высокое» (PNG примерно в 5 раз меньше),
«Низкое» (примерно в 2 раза, почти без видимых потерь) и «Оригинал» (простое копирование). Выбор действует один раз —
при копировании `Download/factorio` в rootfs (окно с прогрессом). Нативный сжиматель — `app/.../cpp/texcompress` (zlib из NDK):
PNG превращается в палитровый (медианное сечение + уточнение палитры k-means, для режима «Низкое» ещё и дизеринг
Флойда–Стейнберга); размер палитры подбирается под целевое соотношение и не опускается ниже 128 (низкое) / 32 (высокое) цветов.
Файл остаётся без изменений, если выигрыш меньше ×1.67, если это не 8-бит PNG без чересстрочности, файл крошечный
(меньше 4 КБ) или изображение больше 20 Мпикс. После копирования создаётся `compression-report.txt` (рядом с логами):
сколько PNG сжато, сколько пропущено и почему, список пропущенных файлов и сколько места занимают остальные типы файлов.
**Звук в этой сборке не сжимается** (нужен кодер Vorbis, его в проекте нет).

### r34-clean: файлы игры

Пункт меню «Файлы игры» — встроенный файловый менеджер с двумя корнями: «Игра» (`rootfs/home/xuser`: скопированная игра,
`.factorio` с модами, конфигом и сохранениями) и «Download». Выйти выше выбранного корня нельзя. Можно открывать папки,
править текстовые файлы (ini, json, cfg, lua, txt…), копировать/переносить/переименовывать/удалять (долгое нажатие),
создавать папки и добавлять файлы (например, моды) через системный выбор файлов.
